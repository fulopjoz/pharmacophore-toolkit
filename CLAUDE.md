## Project Overview

Pharmacophore-Toolkit is an RDKit-based library for building pharmacophore models from crystal structures, docking poses, or SMILES strings. It generates 3D models (PyMOL `.pml` scripts) and 2D/interactive visualizations, with a focus on deterministic consensus pharmacophore generation.

## Architecture

### Dual Pharmacophore Systems

The codebase has two distinct pharmacophore generation approaches:

**Single-Molecule (`pharmacophore/pharmacophore.py`)**
- Class: `Pharmacophore`
- Methods: `calc_pharm()`, `output_features()`, `draw_pharm()`
- Extracts features from one molecule

**Consensus (`pharmacophore/consensus.py`)**
- Class: `PharmacophoreConsensus`
- Uses agglomerative hierarchical clustering (deterministic, NOT DBSCAN)
- Parameters: `tolerance` (spatial, Å) + `occurrence_threshold` (frequency, 0.0-1.0)
- Finds common features across multiple aligned molecules

### Feature Representation Format

All features use: `[feature_type, atom_indices, x, y, z]`
```python
['Donor', (5, 6), 1.234, 5.678, 9.012]  # Single molecule
['Acceptor', (), 2.345, 6.789, 1.234]    # Consensus (empty tuple)
```

### Key Modules

- `pharmacophore/pharmacophore.py`: Main API, `Pharmacophore` class, `generate_consensus_models()`
- `pharmacophore/consensus.py`: Deterministic clustering with `AgglomerativeClustering`
- `pharmacophore/mol_converter.py`: Feature → RDKit Mol conversion for shape alignment
- `pharmacophore/constants.py`: Feature SMARTS definitions and color palettes
- `pharmacophore/draw.py`: `View` class for 2D/3D visualization with py3Dmol

### RDKit Mol Conversion for Shape Alignment

`mol_converter.py` creates molecular fragments at feature positions:
- Donor → NH3 fragment
- Acceptor → O atom
- Aromatic → benzene ring
- Hydrophobe → CH4 fragment

Required for RDKit shape tools (`AlignMol`, `ShapeProtrudeDist`).

## Critical Design Constraints

1. **Determinism is mandatory**: Same input must produce same output. Never use DBSCAN or random-seeded algorithms
2. **Consensus requires 3D conformers**: Input molecules must have `GetNumConformers() > 0`
3. **Consensus assumes pre-aligned molecules**: Use `rdMolAlign.GetO3A` for alignment first
4. **Feature format is sacred**: Breaking `[type, indices, x, y, z]` breaks everything

## Adding New Feature Types

1. Update `constants.FEATURES` dict with SMARTS patterns
2. Update `constants.FEATURE_COLORS` for visualization
3. Update `mol_converter.FEATURE_TO_ELEMENT` mapping
4. Add test in `tests/test_consensus.py`
