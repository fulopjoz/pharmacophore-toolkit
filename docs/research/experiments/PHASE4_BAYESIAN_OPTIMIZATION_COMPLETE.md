- **Impact**: Different clustering behavior despite same parameters

#### 3. Narrow Search Space
- Phase 4 range: tolerance [1.3, 1.7], threshold [0.25, 0.35]
- Phase 3 optimal: tolerance 1.5, threshold 0.3 (within range but not found)
- **Impact**: Bayesian optimization couldn't escape local optimum

#### 4. min_samples Parameter
- Phase 4 explored: min_samples ∈ [1, 2, 3, 4]
- Phase 3 (implicit): min_samples = 2 (DBSCAN default)
- **Impact**: No improvement from tuning this parameter

## Why Bayesian Optimization Failed

### 1. Plateau in Objective Function

The optimizer encountered a **flat response surface** over most of the search space:
- 13/30 runs (43%) achieved identical best AUC
- Tolerance range spanned 0.106 Å with no effect
- Threshold varied across full search space (0.25-0.35) with no effect

**Implication**: Gaussian Process cannot differentiate between configurations when they produce identical outputs. The acquisition function has no gradient to follow.

### 2. Discrete Feature Space

Feature count is a **discrete variable** controlled by clustering:
- 12 features → 0.7279 AUC (worse)
- 13 features → 0.7468 AUC (local optimum)
- **No 12-feature configurations found in search space**

**Implication**: The search space [1.3-1.7, 0.25-0.35] consistently produces 13 features, preventing exploration of the 12-feature region that Phase 3 found.

### 3. Implementation Mismatch

Phase 3 and Phase 4 use **different consensus classes**:

**Phase 3** (`PharmacophoreConsensusWithAlgorithm`):

**Implication**: Subtle differences in feature extraction/filtering produce different feature counts.

### 4. Overfit to Narrow Range

Search space was optimistically narrowed around Phase 3 optimum:
- Phase 2 found: tolerance=1.5, threshold=0.3
- Phase 4 searched: tolerance=[1.3,1.7], threshold=[0.25,0.35]
- **But Phase 3's 12-feature configuration wasn't reproduced**

**Implication**: The narrowing strategy assumed the optimum lies within ±20% of Phase 2 values, but the critical factor was feature count, not precise parameter values.

## Lessons Learned

### 1. Validate Implementation Consistency

**Problem**: Phase 3 and Phase 4 used different consensus classes, causing feature count mismatch.

**Solution**: Always use the **same implementation** when comparing optimization results. Add integration tests to verify parameter equivalence across refactors.

### 2. Feature Count is a Critical Variable

**Problem**: Optimization focused on continuous parameters (tolerance, threshold) but the discrete feature count dominated performance.

**Solution**: Add feature count as an explicit constraint or objective. Explore wider parameter ranges to sample different feature count regions.

### 3. Narrow Search Spaces Can Miss Optima

**Problem**: Narrowing to [1.3-1.7, 0.25-0.35] trapped optimizer in 13-feature region.

**Solution**: Use Phase 2 ranges for Phase 4, or implement **multi-fidelity optimization** where Phase 4 can expand search space if no improvement found.

### 4. Flat Response Surfaces Break Bayesian Optimization

**Problem**: 43% of runs produced identical outputs, providing no gradient information.

**Solution**: 
- Use **multi-objective optimization** (accuracy + speed + simplicity)
- Implement **feature count stratification** (optimize within each n_features bin)
- Consider **SMAC** (Sequential Model-Based Algorithm Configuration) instead of Gaussian Process for discrete/plateau objectives

### 5. Baseline Validation is Critical

**Problem**: Phase 4 ran for 29 minutes without early validation against Phase 3 baseline.

**Solution**: Implement **early stopping** if first 10 runs don't beat baseline. Add checkpointing to resume if needed.
